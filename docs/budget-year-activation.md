# การเตรียมและเปิดใช้ปีงบประมาณ

## แหล่งอ้างอิง

`system_config.current_year` ของแถวล่าสุดเป็นปีหลักเพียงค่าเดียว ระบบตรวจสอบกับตาราง `years` และส่ง `current_year` พร้อม `year_id` ผ่าน `GET /api/v1/system-config/current-year` ทุกหน้าขอทุนใหม่ใช้ผลลัพธ์นี้ ไม่เลือกปีล่าสุดหรือปีปฏิทินแทนเมื่อค่าหายไป จึงไม่ต้องเพิ่มคอลัมน์หรือย้ายข้อมูลฐานข้อมูลสำหรับการเปลี่ยนแปลงนี้

## ขั้นตอนของแอดมิน

1. เพิ่มปีใหม่หรือใช้เมนูคัดลอกโครงสร้างทุนและงบประมาณไปยังปีใหม่ การเตรียมข้อมูลยังไม่เปลี่ยนปีที่ผู้ใช้ยื่นคำขอ
2. เตรียมสถานะทุน งบประมาณ อัตรารางวัล เพดานค่าใช้จ่าย และรอบพิจารณาในปีปลายทาง โดยตรวจจำนวนเงินและวันตัดรอบตามประกาศ
3. ไปที่ตั้งค่าระบบ → ปีงบประมาณและช่วงเวลา เลือกปีปลายทาง แล้วกด “ตรวจความพร้อมของปีที่เลือก”
4. กด “ตรวจความพร้อมและเปิดใช้ปีงบประมาณ” ตรวจรายละเอียดและยืนยัน ระบบบันทึกปีหลักและช่วงเวลาพร้อมกัน

`GET /api/v1/admin/system-config/year-readiness?year=2570` ตรวจว่าปีเปิดใช้งาน มีทุนออนไลน์เปิดรับ มีงบรวมมากกว่า 0 ทุกทุนที่เปิดรับ และมีรอบพิจารณาของปีนั้น ถ้ามีทุนรางวัลตีพิมพ์ จะต้องมีอัตรารางวัลและเพดานค่าใช้จ่ายของปีนั้นด้วย เป็นการตรวจว่ามีข้อมูลพื้นฐาน ไม่ได้ยืนยันความถูกต้องหรือความครบถ้วนของอัตราทุกรายการ วันตัดรอบทุกทุน หรือประกาศ แอดมินต้องทวนรายละเอียดเหล่านี้

`PUT /api/v1/admin/system-config` ตรวจซ้ำใน transaction เมื่อเปลี่ยนปี แม้เรียกตรงโดยไม่ผ่านหน้าเว็บ หากไม่ผ่านจะไม่บันทึกปีใหม่ สามารถส่ง `current_year_id` โดยระบบตรวจให้ตรงกับ `current_year` เมื่อส่งทั้งสองค่า

## คำขอเดิมและหน้าเว็บที่เปิดค้าง

- คำขอใหม่ใช้ปีที่เปิดใช้ และ API ตรวจให้ปี หมวดทุน ทุนย่อย และงบประมาณสัมพันธ์กัน
- หน้าเว็บที่ยังเปิดฟอร์มของปีเก่าจะได้รับ `409 budget_year_changed` เมื่อพยายามสร้างคำขอ ให้กลับไปเลือกทุนใหม่
- คำขอที่บันทึกแล้ว รวมถึงร่าง คง `submissions.year_id` เดิม ไม่ย้ายอัตโนมัติ ยื่นร่างเดิมต่อได้ภายใต้เงื่อนไขสถานะทุนและการตรวจสอบเดิม
- โควตารวมยังเป็นคำเตือนตามพฤติกรรมเดิม ค่า 0 ยังใช้ค่าเริ่มต้น 5 ไม่ได้เปลี่ยนความหมายในงานนี้

## คัดลอกทั้งชุดไปยังปีอื่น

ตั้งค่าทุน → ทุนและปีงบประมาณ → เลือกปีต้นทาง → คัดลอกไปยังปีอื่น โดยเลือก “คัดลอกทั้งชุด” (เปิดเป็นค่าเริ่มต้น) แล้วระบุปีใหม่หรือปีที่มีอยู่และยังไม่มีข้อมูล

`POST /api/v1/admin/funds/copy-year` รับ `copy_all: true` เพิ่มจาก payload เดิม เช่น `{"source_year_id":9,"target_year":"2571","copy_all":true}` คัดลอกหมวดทุน ทุนย่อย รหัสทุนและงบประมาณ อัตราเงินรางวัล วงเงินค่าธรรมเนียม และวันตัดรอบทุกทุนใน transaction เดียว ถ้าส่วนใดผิดพลาดจะ rollback ทั้งชุด รวมถึงปีที่เพิ่งสร้าง API ที่ไม่ส่ง `copy_all` ยังคัดลอกเฉพาะโครงสร้างทุนและงบประมาณตามเดิม

งบที่ใช้แล้วเริ่มเป็น 0 และคงวงเงินจัดสรรจากต้นทาง คงสถานะของอัตราและเงื่อนไขแต่ละรายการ วันตัดรอบเลื่อนตามผลต่างปีงบประมาณ คงเดือน วัน เวลา และขอบเขตทุนเดิม หากเป็น 29 กุมภาพันธ์และปีปลายทางไม่มีวันนี้ จะใช้ 28 กุมภาพันธ์แทน ปีปัจจุบันของระบบและคำขอเดิมไม่ถูกเปลี่ยน

คัดลอกซ้ำทั้งชุดไปยังปีที่มีโครงสร้างทุน อัตรารางวัล วงเงิน วันตัดรอบ หรือคำขออยู่แล้วไม่ได้ (`409`) เพื่อไม่สร้างชุดซ้ำหรือทับข้อมูล แก้ไขรายละเอียดปีปลายทางให้ถูกต้องหลังคัดลอก โดยเฉพาะยอดเงินและวันตัดรอบ ก่อนเปิดใช้ผ่านแท็บระบบ

## นำขึ้นระบบ

นำ API ขึ้นก่อน แล้วจึงนำ frontend ขึ้น ไม่มี migration ใหม่ และไม่ต้องล้างยอดหรือแก้ปีของคำขอเก่า ก่อนนำขึ้นตรวจว่า `current_year` ปัจจุบันตรงกับ `years.year` ที่มีสถานะ active

ตรวจหลังนำขึ้นด้วยบัญชีทดสอบ: ปีที่หน้ารายการทุน ปีในฟอร์มใหม่ และ `year/year_id` ของ `/system-config/submission-usage` ต้องตรงกัน เปิดคำขอเก่าเพื่อตรวจว่ายังแสดงปีเดิม และทดสอบเตรียมปีถัดไปโดยยังไม่เปิดใช้ว่าปีหน้าขอทุนไม่เปลี่ยน
